⟁ AION Invite Machine тестовое · 7 дней

Распределённая сеть инвайтинга в Telegram · Версия 2.0

01 Концепция системы

Invite Machine — распределённая система для автоматического парсинга участников Telegram-чатов и массового добавления (инвайтинга) этих участников в целевые чаты проекта AION.

Проблема: Чтобы набрать аудиторию в городские чаты AION, нужно вручную добавлять людей. 1000 участников = сотни человеко-часов. Автоматизация решает это.

Как работает:

  1. Администратор создаёт кампанию: указывает исходные чаты (откуда брать людей), целевые чаты (куда добавлять) и город
  2. Центральный сервер (VPS) хранит все кампании, собирает статистику, управляет нодами
  3. Ноды — клиентские программы на ноутбуках команды (10+ штук). Каждый нод имеет свой IP
  4. На каждом ноде запущены 2-3 Telegram-аккаунта (купленные, с session_string)
  5. Нод забирает кампании с сервера, парсит участников из исходных чатов, добавляет их в целевой чат
  6. Интервал между действиями: 3-5 минут. Каждый аккаунт делает ~30-40 приглашений в день
🎯 Что должно работать через 7 дней
  • Сервер запущен, админка открывается по паролю
  • Нод запускается на ноутбуке, подключается к серверу
  • В админке создаётся кампания (исходный чат → целевой чат)
  • Нод парсит участников из исходного чата через Telethon
  • Нод добавляет участников в целевой чат (с интервалами)
  • В админке видна статистика: сколько собрано, сколько добавлено

2.2. Коммуникация — HTTP Polling

Ноды не получают задачи от сервера в реальном времени. Они работают по polling-модели:

  • Раз в 5 минут нод опрашивает сервер: GET /api/node/tasks
  • Раз в 60 секунд нод шлёт heartbeat: POST /api/node/heartbeat
  • После завершения кампании нод отсылает статистику: POST /api/node/stats/report
  • Сервер считает нод офлайн, если heartbeat не было >3 минут

05 Обработка Telegram-аккаунтов

5.1. Типы аккаунтов

ТипОтличиеПрогрев
КупленныеЕсть session_string, уже созданы и прогреты продавцомСразу Level 4
СвоиНет session_string, создаются с нуля, требуют код входаПроходят прогрев с Level 0

5.2. Система прогрева (Warm-up)

Цель прогрева — имитировать поведение живого человека, чтобы Telegram не забанил аккаунт. Лимиты растут постепенно:

WARMUP_PROFILES = {
  0: {"dm": 5,  "add": 3,   "label": "Day 1-2"},
  1: {"dm": 10, "add": 5,   "label": "Day 3-4"},
  2: {"dm": 20, "add": 10,  "label": "Day 5-6"},
  3: {"dm": 30, "add": 20,  "label": "Day 7-8"},
  4: {"dm": 50, "add": 30,  "label": "Day 9+"},
}
WARMUP_DAYS = [2, 2, 2, 2, 999]  # дней на каждом уровне

Функция get_warmup_level(account_age_days) вычисляет текущий уровень по возрасту аккаунта. Функция get_daily_limits(phone) возвращает (max_dm, max_add) для этого аккаунта.

5.3. Дневные лимиты

  • Каждый аккаунт имеет лимит на DM и на добавления в день
  • Лимиты хранятся в daily_usage — суммируются по account_phone + action + date
  • can_invite(phone) проверяет: used = get_daily_used(phone, "add"), если used < max_add — можно
  • При каждом успешном действии: inc_daily(phone, action)
  • Если аккаунт исчерпал лимит — нод переключается на другой аккаунт на этом же ноде
  • Если все аккаунты исчерпали лимит — нод останавливается до следующего дня

5.4. Telegram-клиент (AccountManager)

Класс AccountManager управляет созданием и авторизацией Telethon-клиентов:

create_client(acc) -> TelegramClient
  - Если есть session_string: TelegramClient(StringSession(session_string), ...)
  - Если нет: TelegramClient("sessions/phone", ...) — Telethon сам сохранит сессию
  - Если указан proxy: socks5:127.0.0.1:9050 → парсится в proxy_dict

auth_client(client, phone) -> User
  - Вызывает client.get_me() — если успешно, аккаунт уже авторизован
  - Если ошибка — вызывает client.start(phone=phone) — запросит код (через консоль/лог)
  - Сохраняет/обновляет запись в accounts

5.5. Состояния аккаунта

statusЗначениеДействие
activeРаботаетИспользуется в кампаниях

06 Движок инвайтинга — полное описание

6.1. Запуск кампании (run_campaign)

Шаг 1. Парсинг исходных чатов

  1. Для каждого исходного чата из campaign.source_chats:
  2. Взять первый активный аккаунт на ноде
  3. Создать клиента через AccountManager.create_client(acc)
  4. Авторизоваться через auth_client(client, acc.phone)
  5. Получить entity чата: client.get_entity(chat_link)
  6. Собрать участников: client.get_participants(entity, limit=10000)
  7. Отфильтровать: исключить ботов (p.bot), удалённые аккаунты (p.deleted)
  8. Проверить: если контакт уже есть в БД (is_contacted(p.id)) — пропустить
  9. Сохранить нового контакта: save_contact(p, chat_title, campaign.city, node_id)
  10. Пауза 3 секунды между парсингом разных чатов
  11. Отключить клиента: client.disconnect()

Шаг 2. Добавление в целевые чаты

  1. Для каждого целевого чата из campaign.target_chats:
  2. Взять первый активный аккаунт
  3. Авторизоваться, получить entity чата
  4. Перебрать всех новых контактов (из шага 1):
  5. Для каждого контакта — проверить лимиты текущего аккаунта
  6. Если лимит исчерпан — попробовать другой аккаунт на ноде (round-robin)
  7. Если все аккаунты превысили лимиты — прервать кампанию
  8. Вызвать: client(AddChatUserRequest(chat_id, user_id, fwd_limit=0))
  9. Если успешно — mark_added(user_id, chat_id), inc_daily(phone, "add")
  10. Пауза: random.randint(60, 180) секунд (1-3 минуты)
  11. При ошибке — вызывать соответствующий обработчик

6.2. Обработка ошибок Telegram

6.3. Шедулер (CampaignScheduler)

Фоновый цикл, который проверяет расписание:

  • Каждые 30 секунд проверяет таблицу schedule
  • Если текущее время совпадает с запланированным (час + минута) и день недели подходит — запускает кампанию
  • Ждёт 61 секунду после запуска, чтобы не запустить кампанию дважды в одну минуту

6.4. Цикл нода (NodeEngineRunner)

while not stopped:
    1. Запросить GET /api/node/tasks
    2. Если кампаний нет — ждать 60 сек, повторить
    3. Если аккаунтов нет на ноде — ждать 120 сек
    4. Для каждой кампании:
       a. Запустить InviteEngine.run_campaign()
       b. Отправить POST /api/node/stats/report
       c. Пауза 10 сек
    5. Ждать 300 сек (5 мин), повторить

  • Работа с аккаунтами: save_account(), get_accounts(), get_healthy_accounts(), get_warmup_level(), get_daily_limits(), get_daily_used(), inc_daily()
  • Работа с контактами: save_contact(), mark_dm_sent(), mark_added(), mark_error(), mark_clicked(), is_contacted()

  • Статистика: get_stats()
  • Ноды: register_node(), node_heartbeat(), get_offline_nodes()
  • Классы: AccountManager, InviteEngine, CampaignScheduler

server.py — содержит:

  • Flask-приложение с роутами
  • Admin API endpoints
  • Node API endpoints (с Bearer-авторизацией)
  • Middleware login_required (session cookie) и node_auth (Bearer token)

node.py — содержит:

  • Лог: push_log(msg) — хранит последние 500 строк, отдаёт через /api/log
  • Запуск: main() с аргументами --server и --port

10 Что НЕ нужно делать (Scope Cut)

  • Прокси — работаем на чистых IP ноутбуков. Прокси будут в фазе 2.
  • Telegram Premium — работаем без премиума (30-40 инвайтов/день достаточно)
  • Docker/Kubernetes — обычный Python процесс
  • JWT/OAuth — простая Bearer-авторизация по токену
  • Асинхронный сервер (aiohttp/FastAPI async) — Flask синхронный, этого хватит
  • Миграции БД (Alembic) — init_db() через CREATE TABLE IF NOT EXISTS
  • CI/CD — деплой через git pull + перезапуск
  • Мониторинг/алерты — heartbeat + лог в админке
  • Шифрование session_string — храним как есть, доступ к файлам только локальный
  • Отправка DM — в фазе 1 только добавление в чаты (DM могут быть позже)
  • POSTGRESQL вместо SQLite — не нужно, данных мало
  • HTTPS/SSL — в фазе 1 только HTTP (сервер на VPS, ноды локально)
