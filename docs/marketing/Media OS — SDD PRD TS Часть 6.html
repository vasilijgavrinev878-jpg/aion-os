14.2 CI/CD пайплайн (GitHub Actions)

.github/workflows/deploy.yml

```yaml
name: Deploy AION Media OS

on:
  push:
    branches: [main, staging]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Запуск тестов бэкенда
        run: |
          cd backend
          pip install -r requirements-dev.txt
          pytest tests/ --cov=app --cov-report=xml
      - name: Запуск тестов фронтенда
        run: |
          cd frontend
          npm ci
          npm run lint
          npm run test
      - name: Проверка Docker Compose
        run: docker compose config

  build:
    needs: test
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v4
      - name: Сборка и публикация API
        run: |
          docker build -t aion-media/api:latest ./backend
          docker tag aion-media/api:latest ghcr.io/aion-media/api:${{ github.sha }}
      - name: Сборка и публикация Frontend
        run: |
          docker build -t aion-media/frontend:latest ./frontend

  deploy:
    needs: build
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    steps:
      - name: Деплой в продакшн
        run: |
          ssh aion@${{ secrets.DEPLOY_HOST }} \
            "cd /opt/aion-media && \
             git pull && \
             docker compose pull && \
             docker compose up -d --remove-orphans && \
             docker system prune -f"
```

14.5 Проекция на 2028: Мультирегиональная Kubernetes-инфраструктура

ПРОГНОЗИРУЕМОЕ УЗКОЕ МЕСТО: Docker Compose не выдержит >100 видео/день

Почему это важно сейчас: На MVP Docker Compose достаточен, но при 100+ видео/день один хост упрётся в лимиты ресурсов, отсутствие мультирегионального failover приведёт к 4+ часовым инцидентам. Мы проектируем Kubernetes-архитектуру с первого дня, чтобы переход был бесшовным.

Архитектурное решение: Мультирегиональные кластеры на базе cell'ов с Temporal.io оркестрацией, Redpanda для стриминга событий и полной GitOps-инфраструктурой. Каждый cell автономен и может работать независимо.

16.2 Анализ узких мест на каждом уровне масштаба

● Низкий
1 → 10 видео/день (Недели 1-12)
Узкое место: Генерация видео (WAN). 60с на клип, 4 клипа/видео → 4 мин/видео. 10 видео = 40 мин GPU времени. Решение: Один GPU всё ещё достаточен — 40 мин/день оставляет 23ч простоя.
● Средний
10 → 50 видео/день (Недели 13-24)
Узкое место: Время GPU. 50 видео × 4 мин = 200 мин (3.3 часа). Всё ещё выполнимо на одном GPU. Решение: Добавить 1-2 облачных GPU (vast.ai ~$0.30/ч). Стоимость: ~$50-100/мес. Вторичное: LLM инференс — 250 вызовов/день, Ollama справляется.
● Высокий
50 → 200 видео/день (Недели 25-36)
Узкое место: Время GPU (200 × 4 мин = 800 мин = 13.3 часа). Нужны несколько GPU. Решение: 4-6 GPU инстансов (vast.ai/runpod). Раздельные пулы image gen vs video gen. ~$300-500/мес. Вторичное: Пропускная способность Redis → Redis Cluster. Третичное: Записи PostgreSQL → read реплика для дашбордов.
● Высокий
200 → 1000 видео/день (Недели 37-52)
Узкое место: Всё. 1000 × 4 мин = 4000 мин = 66.7 час GPU/день. Нужно ~20-30 GPU 24/7. Решения: GPU-ферма (20-30 A5000/4090, ~$3000-5000/мес). LLM: vLLM вместо Ollama (10x пропускная способность). Image gen: 10 ComfyUI воркеров. Video gen: 20 WAN воркеров. БД: PostgreSQL + 3 read реплики + pgvector. Redis: 6-узловой кластер. MinIO: 8 узлов distributed. API: 10-20 FastAPI реплик за Nginx + HAProxy. CDN: Cloudflare R2 / BunnyCDN.
● Критичный
1 000 → 100 000 видео/день (Enterprise, 2027–2028)
Узкое место: Монолитная БД (PostgreSQL + pgvector). Python GIL под нагрузкой. Redis OOM. Уязвимость одного региона. Проектные решения: Разделение БД: CockroachDB (арендаторы) + ScyllaDB (состояние) + ClickHouse (аналитика) + Qdrant (вектора). Переписывание бэкенда: Rust API Gateway + Go воркеры + Python только для ML. Redpanda/Kafka вместо Redis. Temporal.io вместо Celery. Кластер: 800 L40S + 1200 B200 + 100 Groq LPU = 2 300 GPU. Edge-публикация: 10 000 residential proxy узлов.
● Критичный
100 000 → 10 000 000 видео/день (Global, 2028–2029)
Узкое место: Межъячеистая задержка. Data gravity. Регуляторные требования по регионам. Мульти-петабайтное хранилище. Ultra-Scale решения: Ячеистая архитектура (3+ независимых региона: US-East, EU-Central, AP-South). Гео-распределённое хранение: CockroachDB multi-region Raft, ScyllaDB per-cell, Ceph per AZ. Спекулятивный inference mesh (1.5x throughput). Автономный RLAIF с синхронизацией весов каждые 6ч. Zero-Touch комплаенс: C2PA + региональный watermark + GDPR/EU AI Act. Результат: 10M видео/день с 0.018% инфраструктура-к-доходу. $640M/день при CPM $8.

16.6 Ключевые архитектурные решения для глобального масштаба

РешениеОбоснование
Очередная архитектура (не HTTP между агентами)Агенты развязаны — масштабируются независимо, ретраи независимо, нет каскадных отказов
Stateless воркерыЛюбой воркер может обработать любую задачу. Добавление/удаление воркеров без координации.
Идемпотентная обработка (Temporal + Redpanda)Каждый workflow имеет уникальный execution ID. Детерминированное воспроизведение гарантирует ноль потерь даже при сетевых разделениях.
Многоуровневое объектное хранение (Hot/Warm/Cold)R2 для горячих рендеров, Ceph для 30-дневного тёплого хранения, Glacier для архива. 60% экономии через content-addressed дедупликацию.
Полиглот персистентность (CockroachDB + ScyllaDB + ClickHouse + Qdrant)Каждая БД оптимизирована под свою нагрузку: транзакции (CockroachDB), throughput (ScyllaDB), аналитика (ClickHouse), вектора (Qdrant). Никакой единой точки отказа.
GPU пулы разделены по типу модели + спекулятивный inferenceImage gen, video gen, LLM inference изолированы. Спекулятивный decoding (draft 3B → verify 70B) даёт 3x прирост пропускной способности.
Rust API Gateway + Go Workers + Python MLRust обрабатывает 150k+ запр/сек с суб-мс сериализацией. Go для быстрого выполнения воркеров. Python строго ограничен узлами ML-инференса.
Нейронный семантический кэш промптов (Qdrant)35% всех LLM промптов могут быть обслужены из кэша (в пределах 0.95 косинусной схожести). Экономит $40M+ ежегодно при 10M видео/день.
Все промпты и шаблоны в версионированном DB реестреМожно A/B тестировать, версионировать, авто-откатывать и улучшать промпты без деплоя кода. Непрерывный цикл RLAIF оптимизации.
Residential Proxy Edge Publishing10 000+ географически распределённых узлов публикации предотвращают shadowban. OAuth хранилище с автообновлением устраняет инциденты с истечением токенов.
