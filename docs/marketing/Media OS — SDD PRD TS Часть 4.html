7.2.1 Этап 1: Генерация идей

7.2.6 Этап 6: Генерация видеоклипов

Генерация видео использует WAN 2.1 text-to-video или image-to-video. Агент управляет памятью GPU, планируя по одному клипу за раз:

Планирование генерации видео

1. Проверить доступную память GPU
2. Если < 20 ГБ: использовать CogVideoX (более лёгкая модель)
3. Если 20–24 ГБ: использовать WAN 2.1 (оптимально)
4. Если > 24 ГБ: использовать WAN + более высокое разрешение

Для 30-секундного видео с 4 сценами:
- Клип 1 (6с): WAN, text-to-video, 1080×1920, 36 кадров
- Клип 2 (7с): WAN, image-to-video, 1080×1920, 42 кадра
- Клип 3 (8с): WAN, text-to-video, 1080×1920, 48 кадров
- Клип 4 (7с): WAN, image-to-video, 1080×1920, 42 кадра

Общее время генерации: ~4 мин (в среднем 60с на клип)

7.2.7 Этап 7: Генерация озвучки

1. Текст: voiceover_text из сценария
2. Голос: конфигурация голоса персонажа (высота, скорость, стиль)
3. Модель: Coqui XTTS v2
4. Если у персонажа есть voice_cloning_ref: использовать клонированный голос
5. Иначе: использовать профиль по умолчанию (например, "cheerful_male_v1")
6. Сгенерировать WAV-файл
7. FFmpeg: нормализовать громкость до -14dB LUFS
8. Конвертировать в AAC 128kbps
9. Загрузить в MinIO
10. Вернуть URL

7.2.8 Этап 8: Сборка видео (FFmpeg)

Самый сложный этап. Граф фильтров FFmpeg для типичного 30-секундного шорта:

FFmpeg Filter Complex для сборки видео:

# Входы:
# [0] clip1.mp4 — Сцена 1
# [1] clip2.mp4 — Сцена 2
# [2] clip3.mp4 — Сцена 3
# [3] clip4.mp4 — Сцена 4
# [4] voiceover.m4a — Озвучка
# [5] bg_music.mp3 — Фоновая музыка

ffmpeg -i clip1.mp4 -i clip2.mp4 -i clip3.mp4 -i clip4.mp4 \
       -i voiceover.m4a -i bg_music.mp3 \
       -filter_complex "
  [0][1]xfade=transition=fade:duration=0.5:offset=5.5[scene12];
  [scene12][2]xfade=transition=fade:duration=0.5:offset=12.5[scene123];
  [scene123][3]xfade=transition=fade:duration=0.5:offset=20.5[video];

  [5]volume=0.3[music_low];
  [4][music_low]amix=inputs=2:duration=first[audio];

  [video]drawtext=fontfile=/fonts/bold.ttf:text='Сохрани для Вьетнама 💛':
    x=(w-text_w)/2:y=h-200:fontsize=48:fontcolor=white:
    box=1:boxcolor=black@0.5:boxborderw=10:enable='between(t,25,30)':
    line_spacing=10[out_video]
" -map "[out_video]" -map "[audio]" \
  -c:v libx264 -preset medium -crf 18 \
  -c:a aac -b:a 128k \
  -pix_fmt yuv420p -movflags +faststart \
  final_video.mp4

Расчёт длительности:
  Сцена 1: 6.0с → fade на 5.5с (0.5с crossfade)
  Сцена 2: 7.0с → fade на 12.5с
  Сцена 3: 8.0с → fade на 20.5с
  Сцена 4: 7.0с → конец на 28.0с
  Затухание: 0.5с в конце
  Всего: ~29.0с

⌘ Character System — Единый стандарт вселенной AION

Персонажи AION — это долгоживущие цифровые ассеты с постоянной личностью, историей, внешностью и визуальным ДНК. 8.8 Tier D — Система массовки (Crowd System)

Tier D — это процедурно генерируемые фоновые персонажи, создающие ощущение живого города/мира. Они не имеют идентичности, появляются на один кадр и никогда не повторяются.

СИСТЕМА ГЕНЕРАЦИИ МАССОВКИ:

Сцена определяет:
  ├── Локацию (городской центр, парк, пляж, аэропорт...)
  ├── Время суток (утро, день, вечер, ночь)
  ├── Погоду (солнечно, дождь, туман)
  └── Плотность (пусто, средне, людно, толпа)

Crowd Generator:
  1. Берёт шаблон персонажа (10 базовых типов: мужчина, женщина,
     пара, семья, подросток, пожилой, турист, бегун, офисный)
  2. Применяет случайные вариации:
     - Одежда: 20 шаблонов × 5 цветовых схем = 100 комбинаций
     - Причёска: 10 шаблонов
     - Аксессуары: очки, сумка, зонт, наушники (random)
  3. Распределяет по сцене (алгоритм случайного размещения)
  4. Генерирует анимации: ходьба, стояние, разговор, телефон
  5. Рендерит batch-запросом (все фигуры в одном запросе)

Ограничения:
  - Массовка всегда размыта (глубина резкости)
  - Массовка никогда не смотрит в камеру
  - Массовка не имеет голоса
  - Максимум 1 кадр на появление
Правила Tier D: Массовка не сохраняется в базу. Генерируется on-the-fly. Не требует одобрения. 100% автоматическая генерация. Экономия: занимает 5% GPU-времени от Tier A персонажа.

8.9 Tier E — Роботы, дроны, животные, ИИ-ассистенты

Tier E — все не-людские обитатели вселенной AION. Функциональные сущности, обслуживающие мир и взаимодействующие с персонажами.

Роботы
Сервисные роботы (уборка, доставка), промышленные роботы, роботы-консьержи. Дизайн: матовый чёрный пластик, белые светодиодные индикаторы, минимум деталей. Без антропоморфных черт.
Дроны
Летающие камеры (AION Drones), дроны-курьеры, дроны-наблюдатели. Все с белым энергетическим кольцом — маркер AION. Бесшумные, плавные движения.
Животные
Домашние питомцы (собаки, кошки), городские животные (птицы, белки). Фотореалистичные, AAA-качество. Без мультяшности. Животные не имеют архетипов.
Домашние помощники
Голосовые ассистенты, умные колонки, хаб-дисплеи. Визуализируются как голографический интерфейс, а не физический объект. Белые частицы.
Автономные устройства
Роботы-газонокосилки, автоматические уборочные машины, зарядные роботы для электромобилей. Функциональный дизайн.
ИИ-ассистенты
Виртуальные помощники без физического тела. Появляются как голос + световая индикация (белое кольцо). Не имеют лица, только голос и контекст.
Правила Tier E: Tier E сущности не имеют пола, возраста, биографии. Их дизайн утверждается один раз и не меняется. Не могут быть главными героями видео (только функциональные роли). Роботы и дроны — носители визуального кода AION: чёрный + белое свечение.

8.10 Archetype System — Система архетипов

Каждый персонаж AION обязательно принадлежит одному архетипу. Архетип определяет миссию, поведение, ценности, манеру общения и роль в сюжетах. Архетип — неизменяем.

Explorer
Миссия: Открывать новое, расширять границы. Ценности: Любопытство, смелость, свобода. Общение: Энергичное, воодушевлённое. Роль: Запуск сюжета, открытие мест.
Guardian
Миссия: Защищать, обеспечивать безопасность. Ценности: Ответственность, надёжность, порядок. Общение: Спокойное, уверенное. Роль: Предотвращение кризисов, экспертиза.
Creator
Миссия: Создавать, творить, вдохновлять. Ценности: Красота, мастерство, оригинальность. Общение: Страстное, детальное. Роль: Демонстрация процесса, обучение.
Builder
Миссия: Строить, конструировать, чинить. Ценности: Функциональность, качество, эффективность. Общение: Конкретное, техническое. Роль: Разбор механики, DIY.
Teacher
Миссия: Объяснять, просвещать. Ценности: Ясность, терпение, точность. Общение: Структурированное, понятное. Роль: Объяснение концепций, обучение.
Leader
Миссия: Вести, вдохновлять, объединять. Ценности: Видение, ответственность, харизма. Общение: Уверенное, мотивирующее. Роль: Принятие решений, направление.
Innovator
Миссия: Изобретать, менять правила. Ценности: Прогресс, смелость, vision. Общение: Дерзкое, провокационное. Роль: Презентация новых идей, технологий.
Researcher
Миссия: Исследовать, анализировать. Ценности: Истина, точность, доказательства. Общение: Аналитическое, взвешенное. Роль: Эксперименты, анализ данных.
Guide
Миссия: Направлять, показывать путь. Ценности: Мудрость, терпение, эмпатия. Общение: Тёплое, заботливое. Роль: Проводник в новом месте/опыте.
Strategist
Миссия: Планировать, оптимизировать. Ценности: Эффективность, дальновидность. Общение: Деловое, рациональное. Роль: Финансы, бизнес, инвестиции.
Visionary
Миссия: Видеть будущее, вдохновлять. Ценности: Интуиция, масштаб, потенциал. Общение: Метафоричное, вдохновляющее. Роль: Архитектура, стратегия будущего.
Protector
Миссия: Оберегать, укреплять. Ценности: Сила, стойкость, забота. Общение: Поддерживающее, мотивирующее. Роль: Фитнес, здоровье, безопасность.
Connector
Миссия: Соединять людей, идеи, ресурсы. Ценности: Гармония, отношения, синергия. Общение: Дипломатичное, тёплое. Роль: Связи, события, сервис.
Observer
Миссия: Наблюдать, анализировать. Ценности: Объективность, понимание. Общение: Созерцательное, глубокое. Роль: Комментарий, перспектива, контекст.
Healer
Миссия: Исцелять, восстанавливать. Ценности: Забота, сострадание, здоровье. Общение: Мягкое, успокаивающее. Роль: Здоровье, медицина, восстановление.
Architect
Миссия: Проектировать системы, структуры. Ценности: Порядок, эстетика, функциональность. Общение: Чёткое, системное. Роль: Проектирование, строительство, организация.
Правило архетипов: Архетип — неизменяемая характеристика. Персонаж не может сменить архетип. Архетип определяет базовые параметры генерации промптов. Каждый Tier S и A персонаж имеет ровно один архетип. Tier B, C, D могут иметь «фоновый» архетип по умолчанию (Observer).

8.16 World Integration — Связь персонажей с миром

Каждый персонаж существует не в вакууме — он привязан к определённым странам, городам, районам, зданиям, разделам приложения и услугам AION. Эти связи определяют, в каком контексте персонаж появляется.

ГРАФ СВЯЗЕЙ ПЕРСОНАЖ — МИР:

   Персонаж
      │
      ├── Country (страна происхождения / деятельности)
      ├── City (город, где персонаж «живёт»)
      ├── District (район / локация привязки)
      ├── Building (конкретное здание — кафе, лаборатория)
      ├── App Section (раздел приложения, где персонаж — гид)
      ├── Services (услуги AION, к которым привязан: fintech, health, travel)
      ├── User Segments (типы пользователей, с которыми взаимодействует)

8.17 Versioning & Lifecycle — Версионирование и жизненный цикл

Каждый персонаж проходит через следующие стадии жизненного цикла:

ЖИЗНЕННЫЙ ЦИКЛ ПЕРСОНАЖА:

  ┌──────────┐    ┌──────────┐    ┌───────────┐    ┌───────────┐    ┌───────────┐
  │  DRAFT   │───▶│ ACTIVE   │───▶│  REVIEW   │───▶│ APPROVED  │───▶│ ARCHIVED  │
  │ (черновик)│    │(в работе) │    │(на проверке)│    │(утверждён) │    │(архив)    │
  └──────────┘    └──────────┘    └───────────┘    └───────────┘    └───────────┘
                        │                                                │
                        │ (обновление)                                    │ (восстановление)
                        ▼                                                │
                   ┌──────────┐                                           │
                   │ DRAFTv2  │───────────────────────────────────────────┘
                   └──────────┘

Версионирование по SemVer:
  MAJOR: Полное переосмысление персонажа (новые портреты, LoRA, голос)
  MINOR: Добавление анимаций, эмоций, костюмов
  PATCH: Исправление промптов, оптимизация LoRA

Политика хранения:
  - Tier Ω–B: хранятся все версии бессрочно
  - Tier C: посл. 5 версий
  - Tier D: не версионируются
  - Tier E: текущая версия

Автоматическое архивирование:
  - Tier A+: после 180 дней без использования → предупреждение
  - Tier A+: после 365 дней → автоматический архив
  - Tier B: после 90 дней без использования → архив
  - Tier C: после 60 дней → архив
  - Архивные персонажи не удаляются, а помечаются archived и скрываются из поиска
