1. Что такое AION

AION — операционная система для жизни людей за границей на всех языках мира. Решает ВСЕ бытовые задачи в одном окне: жильё, визы, транспорт, медицина, красота, юристы, финансы и ещё 16 категорий. 23 категории услуг, AI + оператор 24/7, реферальная программа 30% + 20%. Telegram Mini App.
Users × (Categories × Partners × Trust) × AI / (Churn × CAC) = Revenue

Миссия: Дать человеку в любой точке мира доступ к лучшим городским сервисам на его родном языке — без переплаты, без языкового барьера, без риска.

Запуск: Мягкий старт 24 июня 2026 · Платформа: Telegram Mini App · Языки: русский, английский, тайский, вьетнамский (+ все языки мира через AI)

Название: От древнегреческого aiōn — «эон», «эра», «вечность». Отражает масштаб: не временный проект, а инфраструктура на десятилетия.

Ключевая фраза: «Мы не конкурируем с сервисами жилья, транспорта, медицины или экскурсий. Мы конкурируем с хаосом. Для каждого языка и культуры.»

Бюджет: Полностью покрыт основателями. Внешних инвесторов нет. Все основатели — действующие участники, полная занятость.

5. Продукт — Telegram Mini App

Структура интерфейса

  1. Выбор страны — список покрываемых стран
  2. Выбор города — список городов
  3. Главное меню — 4 кнопки:
    • Поисковик (AI, текст + голос)
    • Наши услуги (23 категории, сгруппированы в 10-12 кластеров)
    • Места рядом (Google Maps + рейтинг AION)
    • О городе / афиша
  4. Профиль — история заказов, избранное, рефералы, настройки
  5. Карточка услуги — описание, фото, цена, расстояние, статус
  6. Переход в чат — с менеджером или напрямую к исполнителю
  7. AI-поисковик — текст + голос. AI фильтрует по цене, показывает карточки. Если не находит — передаёт оператору.

Retention (9 причин остаются)

  1. Повторный заказ в 1 клик (история сохраняется)
  2. Подписка (платит → остаётся)
  3. Привычка (легче написать в AION, чем искать)
  4. Накопленная ценность (история, документы, предпочтения)
  5. Бонусы и уровни лояльности
  6. Мультизадачность (23 категории — невозможно заменить одним сервисом)
  7. Доверие (проверенные партнёры, контроль качества)
  8. Живая поддержка (оператор 24/7)
  9. Экосистема (всё в одном приложении)

8. City Governor

Каждый город управляется City Governor — локальным лидером, который отвечает за развитие базы партнёров и пользователей.

Обязанности

  • Поиск и подключение новых партнёров
  • Контроль качества услуг
  • Развитие сообщества пользователей
  • Локальный маркетинг (визитки, плакаты, связи с бизнесом)
  • Обратная связь платформе

Мотивация

  • 20% от комиссии AION со всех заказов в городе (4 уровня: 10/5/3/2%)
  • Бесплатный Premium-статус
  • Эксклюзивные права на город (при выполнении KPI)
  • Приоритетная поддержка от команды AION

9. Invite Machine v2 — ИИ-парсер

Статус: Обкатан, работает, пользователи приходят. Нужно масштабировать.

Как работает

  • Аккаунты ходят по чатам и каналам
  • Общаются с людьми с помощью ChatGPT
  • В шапке профиля ссылка на приложение AION

Старая система (отказались)

Клиентские ноды на каждом ноутбуке → распределённая сеть инвайтинга → добавление людей в чаты через Telegram API. Система warm-up (5 уровней), защита от банов. 30 аккаунтов × 40 инвайтов/день = 1200 инвайтов/день.

Проблемы

  • Аккаунты СНГ дорогие (старые 30 не подходят)
  • Нужно финансирование под закупку

15. Технологический стек

Backend
  • NestJS (на Fastify) — фреймворк
  • Prisma — ORM
  • PostgreSQL — база данных
  • Redis — кеш, сессии, очереди
  • Vitest — тесты
  • ESM-only, TypeScript со strictNullChecks
Frontend
  • Next.js (App Router)
  • React
  • Ant Design — UI-кит
  • Tailwind — стилизация
  • SWR — работа с данными
  • superagent — HTTP-клиент
  • Telegram Mini App SDK
Инфраструктура
  • Docker Compose локально: Postgres, Redis, LocalStack (S3-эмуляция), backend, два фронта
  • CI/CD на GitLab CI: test → build → scan → deploy
  • Hot-reload через volume-монтирование src
Telegram Invite Machine (отдельный репозиторий)
  • aion_engine.py — ядро: Telegram-клиенты (Telethon), AccountManager, InviteEngine
  • server.py — центральный Flask-сервер: админка, управление нодами, кампаниями
  • node.py — клиент-нода с локальной Flask-панелью (порт 5100)
  • 33 аккаунта (покупные, по ~30 руб), загружаются через StringSession

Принципы архитектуры

  • Модульный монолит. Сознательно НЕ микросервисы — для MVP это лишняя сложность.
  • PostgreSQL-first. Одна база, всё крутится вокруг неё.
  • Доступ к данным: Prisma для CRUD/транзакций/админки; сырой SQL — для поиска, агрегаций, ранжирования, графовых и рекурсивных запросов.
  • Сервис-ориентированность: feature-модули — каждый домен (orders, partners, referrals…) самодостаточен.

Чего осознанно избегаем

✕ Микросервисы · ✕ CQRS · ✕ Event sourcing · ✕ Распределённые транзакции · ✕ Kubernetes

Как устроен код

apps/
  backend/   — NestJS, Prisma-схема, миграции, сиды, скрипты
  frontend/  — Next.js, две сборки (Telegram + Админка)

*.module.ts           — регистрация модуля
*.controller.ts       — только транспорт: валидация, вызов сервиса, маппинг ответа
*.service.ts          — бизнес-логика
repositories/         — Prisma и сырой SQL
dto/                  — валидация через class-validator

src/api/
  *-api.ts     — HTTP-запросы
  *-types.ts   — TypeScript-типы
  *-hooks.ts   — SWR-хуки
Правило: контроллеры — ТОЛЬКО HTTP-слой. Никакой бизнес-логики и SQL в контроллерах.

Код-стайл

  • Общий Prettier, ESLint flat-config, Conventional Commits
  • TypeScript strictNullChecks
  • ESM-only модули. Никакого CommonJS.
  • Swagger: каждый эндпоинт документирует все коды ошибок

Изюминка фронта

Один кодбейс — две сборки. Telegram-приложение (.tsx) и админка (.admin.tsx) собираются из одного репозитория через переменную BUILD_TARGET. Есть автоматическая проверка, что Telegram SDK не «протекает» в админ-бандл. Мобайл-first, оптимизация под слабые телефоны и нестабильный интернет.

16. Реферальная система (технически)

Архитектура реферальной системы
  • Две модели: пользователь→пользователь (20/5/3/2% на 4 уровня по дереву referrerId) и пользователь→бизнес (приглашающий = L1 10%, дальше по его цепочке)
  • Леджер начислений с @@unique([orderId, kind, level]) → идемпотентность: повторное завершение заказа не задваивает деньги
  • Баланс вычисляемый, без денормализации
  • Начисление — хук в момент завершения заказа, запись пачкой внутри транзакции
  • Графовые запросы — сырой SQL: рекурсивный CTE для дерева, keyset/cursor-пагинация вместо OFFSET

Все важные потоки — через state machines

Заказы, модерация, выплаты — через явные, валидируемые, идемпотентные переходы статусов. Никаких неявных мутаций.

19. Edge Cases

Базовые принципы:

  • Любая ошибка → Fallback → Контроль → Решение
  • Ошибка не остаётся на пользователе
  • Ошибка не ломает процесс
  • В спорных ситуациях — решение в пользу пользователя

20. Что может пойти не так

Риски:
  • Низкий retention → LTV падает → митигация: качество, AI-персонализация
  • Одноразовое использование → подписка, регулярные услуги
