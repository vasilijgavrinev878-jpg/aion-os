1. О продукте

AION (от др.-греч. aiōn — «эон», «эра», «вечность») — Telegram-first платформа для русскоязычных людей, которые живут или путешествуют в Юго-Восточной Азии. MVP запущен в Нячанге, Вьетнам. Soft launch — 24 июня 2026, full launch — 29 июня 2026.

Суть: человек переехал или приехал — и у него куча бытовых задач (трансфер, жильё, медицина, документы, экскурсии). AION закрывает до 90% таких задач через проверенных локальных партнёров, структурированный каталог услуг и операторов, которые помогают довести заказ.

Что внутри

  • Telegram Mini App — основная поверхность для пользователей. Не нужно скачивать приложение, всё внутри Telegram.
  • Админка для операторов — модерация партнёров, услуги, заказы, выплаты.
  • Единый бот — сам определяет город пользователя.
  • 22 категории услуг с первого дня: жильё, медицина, визы, трансферы, экскурсии, уборка, красота, доставка еды, спорт, юристы, SOS и другие.
  • SOS-кнопка — 6 категорий экстренной помощи, SLA 5 минут, GPS-координаты.
Важно: мы НЕ маркетплейс-клон и НЕ «ещё один AI-чатбот». Мы — операционный слой для жизни за границей: оркестрация услуг плюс доверие и координация. Операторы 24/7, AI —辅助, человек принимает решения.

География

Вьетнам (Нячанг, Дананг, Хошимин, Ханой, Фукуок, Муйне, Вунгтау), Таиланд (Паттайя, Пхукет, Бангкок, Чиангмай), Турция, Грузия, ОАЭ, Россия и далее 25+ городов в 10+ странах.

2. О компании

Статус

Bootstrapped-стартап. Никаких внешних инвесторов. Полный бюджет покрыт основателями. Работаем с июня 2026, продукт уже в продакшене, есть первые заказы и партнёры.

Бизнес-модель

  • Комиссия с каждой транзакции (~10%, обсуждается индивидуально с каждым партнёром)
  • Подписки для бизнеса (премиум-инструменты для партнёров) — цель 12% выручки
  • Премиум-размещение — дополнительная видимость для лидеров категорий — цель 8% выручки

Реферальная программа (ядро роста)

  • Пользовательская: 30% комиссии платформы, 4 уровня (20+5+3+2%), пожизненно
  • City Governor: 20% комиссии, 4 уровня (10+5+3+2%), для локальных партнёров
  • ~40% пользователей приходят по реферальным ссылкам с CAC = $0

Геймификация — LVLUP

11 уровней пользователей, 10 уровней исполнителей. 1 XP = $1 комиссии платформы. На 11 уровне — 0% комиссия навсегда. Ежедневные квесты, ачивки, коллекции, колесо фортуны.

4. Технический стек

Backend

  • NestJS (на Fastify) — фреймворк
  • Prisma — ORM
  • PostgreSQL — база данных
  • Redis — кеш, сессии, очереди
  • Vitest — тесты
  • ESM-only, TypeScript со strictNullChecks

Frontend

  • Next.js (App Router)
  • React
  • Ant Design — UI-кит
  • Tailwind — стилизация
  • SWR — работа с данными
  • superagent — HTTP-клиент
  • Telegram Mini App SDK

Инфраструктура

  • Docker Compose локально: Postgres, Redis, LocalStack (S3-эмуляция), backend, два фронта
  • Hot-reload через volume-монтирование src
  • CI/CD на GitLab CI: test → build → scan → deploy

Авторизация

  • Telegram-first: валидируем initData от Telegram по HMAC с токеном бота → выдаём JWT
  • Админка: отдельная сессия на HttpOnly-cookie
ESM-only: весь код на ESM-модулях. Никакого CommonJS. TypeScript со strictNullChecks. Prettier + ESLint flat-config. Conventional Commits.

Изюминка фронта

Один кодбейс — две сборки. Telegram-приложение (.tsx) и админка (.admin.tsx) собираются из одного репозитория через переменную BUILD_TARGET. Есть автоматическая проверка, что Telegram SDK не «протекает» в админ-бандл. Мобайл-first, оптимизация под слабые телефоны и нестабильный интернет.

5. Архитектура и принципы

Ключевой посыл: это MVP. Приоритеты — скорость итераций, простота, отлаживаемость, надёжность. Не строим «идеальную масштабируемую архитектуру наперёд».

Принципы

  • Модульный монолит. Сознательно НЕ микросервисы — для MVP это лишняя сложность.
  • PostgreSQL-first. Одна база, всё крутится вокруг неё.
  • Доступ к данным: Prisma для CRUD/транзакций/админки; сырой SQL — для поиска, агрегаций, ранжирования, графовых и рекурсивных запросов.
  • Сервис-ориентированность: feature-модули — каждый домен (orders, partners, referrals…) самодостаточен.

Чего осознанно избегаем

✕ Микросервисы
✕ CQRS
✕ Event sourcing
✕ Распределённые транзакции
✕ Kubernetes

Глобальный конвейер запроса

  1. Rate-limiter
  2. Интерсептор — оборачивает все ответы в единый формат {data, success}
  3. Централизованный фильтр ошибок (типизированные исключения, никаких сырых SQL-ошибок наружу)

Все ручки под /v1/.

База данных

Сейчас SQLite (data/invite.db) — для быстрого старта. Плановый переход на PostgreSQL при масштабировании.

  frontend/  — Next.js, две сборки (Telegram + Админка)

Правило: контроллеры — ТОЛЬКО HTTP-слой. Никакой бизнес-логики и SQL в контроллерах.

Frontend (на каждый домен)

src/api/
  *-api.ts     — HTTP-запросы
  *-types.ts   — TypeScript-типы
  *-hooks.ts   — SWR-хуки

Telegram Invite Machine (отдельный репозиторий)

Параллельно существует инструмент для приглашений в Telegram-чаты городов:

  • aion_engine.py — ядро: Telegram-клиенты (Telethon), AccountManager, InviteEngine, прогреваем аккаунтов, БД, планировщик кампаний, node-регистрация/heartbeat
  • server.py — центральный Flask-сервер: админка, управление нодами, кампаниями, расписанием, контактами
  • node.py — клиент-нода с локальной Flask-панелью (порт 5100)
  • 33 аккаунта (покупные, по ~30 руб), загружаются через StringSession, прогрева 4+ дня
  • Архитектура: центральный сервер (VPS) + клиентские ноды (ноутбуки команды), каждая на своём домашнем IP

7. Что технически интересно — примеры

Хорошие истории, чтобы показать глубину и заодно нащупать уровень кандидата.

🔄 State machines

Все важные потоки (заказы, модерация, выплаты) — через явные, валидируемые, идемпотентные переходы статусов. Никаких неявных мутаций.

🌳 Реферальная система (свежая большая фича)

Отличный кейс для обсуждения на собеседовании:

  • Две модели: пользователь→пользователь (20/5/3/2% на 4 уровня по дереву referrerId) и пользователь→бизнес (приглашающий = L1 10%, дальше по его цепочке)
  • Леджер начислений с @@unique([orderId, kind, level]) → идемпотентность: повторное завершение заказа не задваивает деньги
  • Баланс вычисляемый, без денормализации
  • Начисление — хук в момент завершения заказа, запись пачкой внутри транзакции
  • Хороший баг для обсуждения: при прямом джойне начислений и заказов получался fan-out — сумма умножалась на количество заказов и раздувалась. Чинится предагрегацией каждой таблицы в отдельных подзапросах до джойна. (Можно дать кандидату как задачку «почему сумма неверная?»)
  • Графовые запросы — сырой SQL: рекурсивный CTE для дерева, keyset/cursor-пагинация вместо OFFSET

⚡ Производительность

  • Все списки пагинируются
  • Без SELECT *
  • Индексы обязательны
  • Тяжёлые запросы проходят EXPLAIN ANALYZE

🔐 Telegram-авторизация

Валидация initData от Telegram через HMAC с токеном бота → JWT. Админка — отдельная сессия на HttpOnly-cookie. Telegram-first подход.

11. Почему 4% — это состояние

Ищем 3 full-stack TypeScript разработчиков в ключевую команду. Техническая команда: CTO + 3 разработчика.

Мы bootstrapped-стартап без внешних инвесторов. 4% сейчас — это не «размытая доля после 5 раундов». Это чистая доля в компании, которая растёт с нуля до миллионов. Доли основателей фиксированы, новых раундов с размытием не планируется.

Математика

Консервативная проекция по нашей стратегии (категории услуг, 22 направления, 25+ городов):

ПериодКомиссия / месОценка компании (x12)Ваши 4%
Сейчас (июль 2026)$0 → $10K——
Месяц 12 (июнь 2027)$600K/мес~$7.2M~$288K
Месяц 24 (июнь 2028)$2.5M/мес~$30M~$1.2M
Месяц 60 (июнь 2031)$30M/мес~$360M~$14.4M
Простыми словами: через год твои 4% могут стоить ~$300K. Через 5 лет — >$14 млн. И это консервативный сценарий (услуги для русскоязычных, 25 городов). С выходом на английский рынок (месяц 6) и глобальную экспансию цифры умножаются.

Почему 4% — это много

  • Основатели (Влад, Василий) имеют по ~20% — ты получаешь в 5 раз меньше, чем создатели компании. На старте это честно.
  • Людмила (CCO) получила 9% за операционное управление всей компанией. Разработчик получает 4% — почти половину от COO, просто за код.
  • Ты заходишь наравне с ключевыми сотрудниками. 4% — это уровень топ-менеджмента. В любой другой компании на такой стадии разработчик получил бы 0.5-1%.
  • Без инвесторов — долю не размывают раунды. Мы не берём деньги снаружи. То, что ты получил, — твоё.

Что ещё важно

  • 4% — это не опционы, а доля (equity). Ты совладелец, а не наёмник с обещанием.
  • Доход с первого дня: реферальная программа (30% комиссии платформы с приглашённых) + внутренние услуги компании без комиссии.
  • Работа из любой точки мира. Команда распределённая.
  • Короткие итерации, фичи в продакшн каждую неделю. Не бюрократия, а стройка.
  • Реальный продукт с реальными пользователями и деньгами. Не «сделаем стартап и умрём».
  • Влияние на архитектуру и стек. Ты формируешь техническое лицо продукта.
  • NestJS, Next.js, PostgreSQL, Prisma, Redis, Docker. Никаких микросервисов, K8s и прочего оверинжиниринга.
